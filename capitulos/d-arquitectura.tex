\subsection{Datos, documentos y conversación}\label{d-1}

La API autentica, autoriza y consulta; el processor ejecuta la ingesta asíncrona. Los estados operativos, textos y originales se almacenan por separado, según la tabla~\ref{tab-d1}. Esta separación no crea una transacción distribuida ni demuestra mayor rendimiento; confirmar la publicación en RabbitMQ no garantiza procesado exactamente una vez. \cite{arquitectura-final}

La ingesta acepta texto o archivos. El navegador obtiene una URL firmada, sube el original a MinIO y solicita confirmación. El backend valida tamaño, contenido y formato antes de encolar. El processor descarga, extrae texto en un entorno aislado, fragmenta, genera embeddings y persiste resultados; sólo entonces retira el original. La caducidad limpia subidas abandonadas. El artefacto participa en descarga y extracción, no es sólo un metadato. \cite{arquitectura-final}

El recorrido determinista resuelve solicitudes explícitas de gasto, presupuestos, propiedad y anomalías con reglas y recuperación documental. El generativo se activa en backend y processor: la API verifica cliente y propietario, registra la operación y llama por red privada, con firma HMAC ---autenticación mediante clave compartida--- y protección contra reutilización. Se recupera contexto una vez por intento, antes del borrador, y se transmiten texto, estado y fuentes al navegador. Historial y operaciones permiten consultar, detener y reanudar. El modelo no ejecuta SQL ni elige herramientas FinOps. \cite{arquitectura-final}

La ingesta de costes usa una API Azure simulada y muestras públicas o sintéticas. Las consultas agregan registros completados por intervalo y moneda; presupuestos y anomalías aplican reglas sobre gasto observado, sin previsiones ni ahorro acreditado. La recuperación híbrida está implementada, apagada por defecto y requiere preparar el índice. La calidad del chat se evalúa en h. \cite{arquitectura-final}

\subsection{Seguridad, operación y entrega}\label{d-2}

La autorización exige token firmado, membresía y cliente permitido. Las conversaciones pertenecen a su propietario y los documentos al cliente autorizado. El processor comprueba propietario y reserva de gasto; su API de chat no publica puertos al exterior. Las credenciales usan configuración protegida. Estos controles no certifican revocación completa, autenticación multifactor ni endurecimiento productivo. \cite{arquitectura-final}

Compose reproduce dependencias y datos simulados; publicar sus puertos, CockroachDB local o la previsualización del frontend exige controles adicionales. Los identificadores de petición correlacionan logs; Prometheus y Grafana aportan métricas, sin trazabilidad distribuida completa ni receptor externo de alertas. CI/CD y ensayos se detallan en f/h. \cite{arquitectura-final,ci-final}

Los adaptadores PostgreSQL, Cognito y Bedrock están implementados y probados localmente o sin conexión. Dos pipelines manuales crean y retiran un ciclo desechable mediante CodePipeline, CodeBuild y CDK/CloudFormation; Terraform es una alternativa, no el motor de esos pipelines. Las capacidades AWS están apagadas por defecto y no se acredita despliegue de aplicación, login real Cognito ni invocación Bedrock. \cite{arquitectura-final,aws-ensayo,terraform-validacion}
