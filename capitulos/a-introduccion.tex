\section{Introducción y resumen ejecutivo}\label{a-0}

Gastar en la nube es fácil; entender el gasto, no. Las startups, los equipos pequeños y los desarrolladores independientes acumulan facturas de proveedores cloud sin visibilidad real de dónde se va el dinero, y sin un equipo de FinOps ni tiempo para analizarlo a mano. Economicon nace para cerrar esa brecha: entender en qué se está yendo el dinero de la nube no debería requerir un máster en facturas ni un equipo dedicado.

Este documento presenta la memoria del proyecto Economicon, un asistente FinOps orientado a personas que no son expertas en FinOps. El alcance de este Trabajo Fin de Máster es el vertical de Microsoft Azure: sobre un conjunto de datos públicos de costes de Azure, servido a través de una API de Azure Cost Management simulada, la solución ingiere y normaliza el gasto, calcula indicadores accionables, detecta gasto innecesario y responde preguntas en lenguaje natural mediante un agente conversacional apoyado en recuperación aumentada por generación (RAG).

\subsection{Resumen ejecutivo}\label{a-6}

\begin{itemize}
\item
  \begin{quote}
  \textbf{Problema:} falta de visibilidad y de tiempo para analizar el gasto cloud en organizaciones sin función FinOps.
  \end{quote}
\item
  \begin{quote}
  \textbf{Solución:} un asistente que convierte datos de coste de Azure en indicadores claros, alertas de gasto anómalo y respuestas conversacionales con fuentes citadas.
  \end{quote}
\item
  \begin{quote}
  \textbf{Arquitectura:} monorepo con backend FastAPI, frontend React, procesamiento asíncrono sobre RabbitMQ, persistencia en CockroachDB, base vectorial pgvector y acceso a modelos de lenguaje vía LiteLLM sobre OpenRouter.
  \end{quote}
\item
  \begin{quote}
  \textbf{Enfoque de IA:} uso de modelos preentrenados a través de un gateway, sin fine-tuning; la personalización al dominio se consigue con RAG sobre los datos de coste y la documentación FinOps.
  \end{quote}
\item
  \begin{quote}
  \textbf{DevOps:} integración continua, versionado de decisiones con OpenSpec y ADR, protección de ramas y flujo de pull requests revisados.
  \end{quote}
\item
  \begin{quote}
  \textbf{Alcance del MVP:} solo Azure, dataset público y sin conexión a un tenant real; el objetivo es demostrar el circuito completo dato → analítica → asistente de forma reproducible.
  \end{quote}
\end{itemize}

\textbf{Nota sobre esta versión.} Se trata de una propuesta de memoria: el contenido de arquitectura, diseño de IA y DevOps refleja el estado real del proyecto, mientras que los resultados de evaluación se marcan como pendientes hasta completar la ejecución sobre el sistema desplegado.
